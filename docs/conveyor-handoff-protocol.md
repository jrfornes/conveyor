# Conveyor Handoff Protocol — Specification

**Status:** Draft v0.1, for PRD v0.2 (MVP)
**Date:** 3 September 2026
**Audience:** whoever (human or agent) implements `handoff.sh`, `role-loop.sh`, `merge.sh`, and the `conveyor` CLI; and the authors of `constitution/handoffs.md`, which is the agent-facing translation of this document.

This document is normative. Where the PRD and this document disagree, this document wins for anything about file formats, directory layout, and state transitions; the PRD wins for scope.

Conventions: MUST / MUST NOT / SHOULD as in RFC 2119. "Rename" always means an atomic same-filesystem `rename(2)`. Timestamps are UTC ISO 8601 to the second: `2026-09-03T14:15:02Z`.

---

## 1. Actors and identity

| Actor | Identity source | May run |
|---|---|---|
| `operator` | The human, via the `conveyor` CLI. A pseudo-role with its own outbox. | `conveyor task/status/log/resume/start/stop` |
| `coder` | `CONVEYOR_ROLE=coder` exported by its loop | `handoff.sh` |
| `reviewer` | `CONVEYOR_ROLE=reviewer` exported by its loop | `handoff.sh` |
| `loop` (one process per role) | Started by `conveyor start` | `role-loop.sh`, `merge.sh` |

Role names MUST match `^[a-z][a-z0-9-]*$` (no underscores; underscores are separators in filenames). `operator` and `done` are reserved and MUST NOT appear as role names in `conveyor.conf`.

Every script reads identity from `CONVEYOR_ROLE` and `CONVEYOR_WORKTREE`. No script accepts identity as an argument.

## 2. Directory layout

### 2.1 Repository root

```
<repo>/
  conveyor.conf
  constitution.md
  constitution/
    engineering.md  workflow.md  handoffs.md
  roles/
    coder.md  reviewer.md
  project.md
  tasks/
    <task-name>.md            committed; operator intent
  .worktrees/                 gitignored
    coder/
    reviewer/
  .conveyor/                  gitignored
    board.tsv
    board.lock/               mkdir-style lock (§8.2)
    roles/
      operator/ coder/ reviewer/      each per §2.3
    needs-human/
      <task-name>/
        item.handoff
        reason
    logs/
      <role>/
        <task-name>_<id>_a<attempt>.jsonl
```

### 2.2 Worktree (`.worktrees/<role>/`)

A full checkout on branch `conveyor-<role>`, plus:

```
tmp/                                    scratch; agent writes drafts here
.cursor/rules/conveyor-role.mdc         generated by conveyor start; gitignored
.git                                    (worktree link file)
```

`.git/hooks` is shared across worktrees; the byline hook (§7.4) is installed once in the main repo.

### 2.3 Role queue directory (`.conveyor/roles/<role>/`)

```
outbox/
  tmp/            validator writes here, then renames into outbox/
sent/             delivered handoffs, kept forever (audit trail)
failed/           malformed or undeliverable files, with a .reason sidecar
inbox/
  tmp/            sender's loop writes here, then renames into new/
  new/
  in_process/     at most one file, except during recovery (§6.1)
  completed/
seq               single line: last issued sequence number (integer)
seq.lock/         mkdir-style lock for seq
audit_pending/
  <task-name>.fp  see §5
loop.lock/        mkdir-style lock; contains pid file
```

`operator` has only `outbox/`, `outbox/tmp/`, `sent/`, `seq`, `seq.lock/`. It has no inbox.

**Write ownership.** Exactly one actor may create files in each directory:

| Directory | Creator | Mover-out |
|---|---|---|
| `<role>/outbox/tmp`, `<role>/outbox` | `handoff.sh` (or `conveyor task` for operator) | `<role>`'s loop |
| `<role>/sent` | `<role>`'s loop | nobody |
| `<role>/failed` | `<role>`'s loop | operator, by hand |
| `<recipient>/inbox/tmp`, `inbox/new` | sender's loop | recipient's loop |
| `<role>/inbox/in_process` | `<role>`'s loop | `<role>`'s loop |
| `<role>/inbox/completed` | `<role>`'s loop | nobody |
| `<role>/audit_pending` | `handoff.sh` | `handoff.sh` |
| `needs-human/` | any loop | `conveyor resume` |
| `board.tsv` | `handoff.sh`, loops, `conveyor task/resume` — under `board.lock` | — |

## 3. Handoff file format

### 3.1 Grammar

```
handoff   = header* NEWLINE body
header    = key ":" SP value NEWLINE
key       = ^[a-z][a-z_-]*$
value     = one line, no leading/trailing whitespace, non-empty
body      = zero or more lines (free text)
```

- Header keys are lowercase. Each key appears at most once.
- The first blank line ends the headers. Everything after it is the body, verbatim.
- Encoding UTF-8, LF line endings. Files end with a newline.
- Header order in the file is: agent headers, then validator headers, then loop headers, each in the order listed in §3.2. Order is normative so fingerprints (§5) and diffs are stable.

### 3.2 Headers

| Key | Written by | Value | Required |
|---|---|---|---|
| `to` | agent / operator | role name, or `done` | yes |
| `task` | agent / operator | task name matching `^[a-z0-9][a-z0-9.-]*$`, must exist as `tasks/<task>.md` at `commit` | yes |
| `verdict` | agent / operator | `ready` \| `pass` \| `findings` | yes |
| `type` | validator | always `git_handoff` | yes |
| `id` | validator | `<from>-<seq>` where `<seq>` is 6-digit zero-padded (§3.4) | yes |
| `from` | validator | `CONVEYOR_ROLE`, or `operator` | yes |
| `commit` | validator | 10 lowercase hex chars, canonical abbreviation of worktree HEAD (§4.4) | yes |
| `task_id` | validator | copied from `board.tsv` for `task` (§8) | yes |
| `created_at` | validator | timestamp | yes |
| `enqueued_at` | sender's loop, at delivery | timestamp | after delivery |
| `dequeued_at` | recipient's loop | timestamp | once in process |
| `attempt` | recipient's loop | integer ≥ 1; rewritten on each agent invocation | once in process |
| `session` | recipient's loop | Cursor session id from the last run's stream-json, if any | optional |
| `completed_at` | recipient's loop | timestamp | once completed |
| `outcome` | recipient's loop | `forwarded` \| `merged` \| `parked` \| `failed` | once completed |

Any header not in this table is an error (`E_UNKNOWN_HEADER`). Agent drafts containing any header not in the "agent / operator" rows are rejected (`E_RESERVED_HEADER`); this is the rule that stops an agent from typing its own SHA.

**Permitted `(from, to, verdict)` triples.** The validator rejects anything else (`E_BAD_ROUTE`):

| from | to | verdict | Meaning |
|---|---|---|---|
| `operator` | `coder` | `ready` | New task, or resumed task |
| `coder` | `reviewer` | `ready` | Work claimed complete |
| `reviewer` | `coder` | `findings` | Not accepted; findings in the commit message |
| `reviewer` | `done` | `pass` | Accepted |

Pipeline order is derived from `conveyor.conf`; the table above is what it derives to for the MVP two-pack. Implementations MUST compute it from the config, not hardcode it.

### 3.3 Body

The validator fills the body with the full commit message of `commit` (`git log -1 --format=%B`), including the byline. Agents MUST NOT write a body in the draft (`E_DRAFT_HAS_BODY`). For a `findings` verdict this is where the reviewer's findings live; for `ready` it is the coder's summary of what was done and how it was verified.

The dashboard rule from the north star carries over: **no script ever edits a body**. Loops append headers only.

### 3.4 Sequence numbers and ids

- `seq` holds one integer. Missing file means 0.
- To issue: acquire `seq.lock/` (§8.2), read, increment, write to `seq.tmp`, rename to `seq`, release.
- `id` = `<from>-<seq>` zero-padded to 6 digits: `coder-000012`.
- Ids are unique per role forever. Rebuilding `.conveyor/` from scratch resets them, which is why `sent/` is kept.

### 3.5 Filename

```
<created_at_compact>_<seq>_from_<from>_to_<to>.handoff
```

`created_at_compact` = `created_at` with `-` and `:` removed: `20260903T141502Z`. Example:

```
20260903T141502Z_000012_from_coder_to_reviewer.handoff
```

Filenames exist so `ls` sorts chronologically and reads sensibly. **Headers are authoritative.** A loop that finds a mismatch between filename and headers moves the file to `failed/` with reason `filename-header-mismatch`.

### 3.6 Draft file (what the agent writes)

Three lines, in `./tmp/` inside the worktree:

```
to: reviewer
task: cave-setup
verdict: ready
```

Trailing blank lines are tolerated. Anything else is rejected with a specific code (§4.5).

### 3.7 Example after delivery and processing

```
to: coder
task: cave-setup
verdict: findings
type: git_handoff
id: reviewer-000004
from: reviewer
commit: 9f3c2a71be
task_id: 20260903T140011Z-cave-setup
created_at: 2026-09-03T14:31:07Z
enqueued_at: 2026-09-03T14:31:08Z
dequeued_at: 2026-09-03T14:31:09Z
attempt: 1
session: 7c1d...
completed_at: 2026-09-03T14:44:52Z
outcome: forwarded

Review: cave-setup

1. tasks/cave-setup.md §2 requires the config loader to reject unknown keys.
   `load_config` in src/config.py:41 accepts them silently. No test covers it.
2. Test `test_loader_roundtrip` asserts on the fixture it just wrote; it cannot fail.

By reviewer.
```

## 4. `handoff.sh` — the validator

Usage: `handoff.sh <draft-path>`. Exit 0 on success (handoff installed in outbox), exit 2 on `AUDIT_REQUIRED`, exit 1 on any other error. All output to stdout, one error per run, formatted as §4.5.

### 4.1 Preconditions

1. `CONVEYOR_ROLE` and `CONVEYOR_WORKTREE` set; cwd is inside `CONVEYOR_WORKTREE` (`E_ENV`).
2. `<draft-path>` resolves inside `CONVEYOR_WORKTREE/tmp/` (`E_DRAFT_PATH`). Symlinks are resolved first.
3. Worktree is clean: `git status --porcelain` is empty (`E_DIRTY`). Uncommitted work is not handed off.
4. HEAD is on branch `conveyor-<role>` (`E_WRONG_BRANCH`).
5. The role's `inbox/in_process/` contains exactly one item, and its `task` equals the draft's `task` (`E_NO_INBOUND`, `E_TASK_MISMATCH`). A role may only hand off the task it is processing.

### 4.2 Draft validation

In this order, stopping at the first failure:

1. Parse headers per §3.1 (`E_PARSE`).
2. No body (`E_DRAFT_HAS_BODY`).
3. Only `to`, `task`, `verdict` present (`E_RESERVED_HEADER` for any key in §3.2's non-agent rows; `E_UNKNOWN_HEADER` otherwise); all three present (`E_MISSING_HEADER`).
4. `to` is a role in `conveyor.conf` or `done` (`E_BAD_RECIPIENT`).
5. `verdict` is one of the three values (`E_BAD_VERDICT`).
6. `(from, to, verdict)` is a permitted triple (`E_BAD_ROUTE`).
7. `tasks/<task>.md` exists at HEAD (`E_TASK_FILE`).
8. `task` has a row in `board.tsv` and its `lane` equals `from` (`E_NOT_MY_TASK`).

### 4.3 Commit validation

1. HEAD's commit message last non-empty line matches `^By <from>\.$` (`E_NO_BYLINE`). This is how `--no-verify` is detected.
2. HEAD is not already the `commit` of the inbound handoff in `in_process/` when `verdict` is `ready` (`E_NO_CHANGE`). A coder must commit something; a reviewer with verdict `findings` MUST also commit (its findings live in the commit message — an empty commit `git commit --allow-empty` is the expected form). A reviewer with `pass` MAY hand off the inbound commit unchanged; `E_NO_CHANGE` does not apply to `pass`.

### 4.4 Commit canonicalization

`commit` = `git rev-parse --short=10 HEAD`. The validator then checks `git rev-parse --verify --quiet <commit>^{commit}` resolves to exactly HEAD (`E_AMBIGUOUS_SHA`; practically impossible at 10 chars, but the check is cheap and the property matters for `merge.sh`).

### 4.5 Error output format

```
<CODE>: <one-line problem>
  <repair line 1>
  <repair line 2>
```

Codes and messages are part of the interface; `constitution/handoffs.md` quotes them. Full list:

| Code | Problem | Repair text (verbatim) |
|---|---|---|
| `E_ENV` | CONVEYOR_ROLE or CONVEYOR_WORKTREE not set | You are not running inside a Conveyor role loop. Stop and report this. |
| `E_DRAFT_PATH` | draft is outside ./tmp/ | Write the draft to ./tmp/handoff.txt inside your worktree and run handoff.sh ./tmp/handoff.txt |
| `E_DIRTY` | worktree has uncommitted changes | Commit or discard all changes, then retry. Handoffs carry commits, not working trees. |
| `E_WRONG_BRANCH` | HEAD is not conveyor-<role> | Run: git checkout conveyor-<role>. Do not create or switch branches. |
| `E_NO_INBOUND` | nothing in inbox/in_process | You have no task in process. Do not hand off. Finish your run. |
| `E_TASK_MISMATCH` | draft task ≠ in-process task | Your in-process task is <task>. Set `task: <task>`. |
| `E_PARSE` | line <n> is not `key: value` | Each line must be `key: value` with lowercase key and a single space after the colon. |
| `E_DRAFT_HAS_BODY` | draft has content after a blank line | Remove everything after the three header lines. Prose belongs in your commit message. |
| `E_RESERVED_HEADER` | header `<key>` is filled by the system | Delete the `<key>` line. Never write from, commit, id, type, task_id or timestamps yourself. |
| `E_UNKNOWN_HEADER` | header `<key>` is not recognised | Only `to`, `task` and `verdict` are allowed. |
| `E_MISSING_HEADER` | `<key>` is required | Add `<key>: <value>`. |
| `E_BAD_RECIPIENT` | `<to>` is not a role | Valid recipients: <list from config>, done. |
| `E_BAD_VERDICT` | `<verdict>` is not valid | Valid verdicts: ready, pass, findings. |
| `E_BAD_ROUTE` | <from> may not send `<verdict>` to `<to>` | As <from> you may send: <permitted rows for this role>. |
| `E_TASK_FILE` | tasks/<task>.md not at HEAD | The task file must be committed. Do not create task files; report this. |
| `E_NOT_MY_TASK` | board lane for <task> is <lane>, not <from> | This task is not in your lane. Do not hand off. Finish your run and report this. |
| `E_NO_BYLINE` | HEAD commit lacks `By <from>.` | Amend the commit without --no-verify: git commit --amend --no-edit |
| `E_NO_CHANGE` | HEAD equals the inbound commit | You have not committed anything. Commit your work (or, as reviewer, an empty commit carrying findings) and retry. |
| `E_AMBIGUOUS_SHA` | 10-char abbreviation is ambiguous | Report this to the operator; it requires a longer abbreviation. |
| `E_LOCK` | could not acquire a lock within 30 s | Retry once. If it fails again, report it. |
| `AUDIT_REQUIRED` | see §5 | see §5 |

### 4.6 Installation (success path)

1. Run the audit gate (§5). If it returns "challenge", print `AUDIT_REQUIRED` and exit 2.
2. Issue `seq` (§3.4) and compute `id`, `created_at`, filename.
3. Read `task_id` from `board.tsv` under `board.lock`.
4. Write the complete file (agent headers, validator headers, blank line, body from `git log -1 --format=%B`) to `outbox/tmp/<filename>`.
5. Rename to `outbox/<filename>`.
6. Delete `audit_pending/<task>.fp`.
7. Print `OK: <id> queued for <to>` and exit 0.

Step 2 happens after step 1 so a challenged submission never consumes a sequence number.

## 5. The audit gate

Purpose: force one re-read between "I think I'm done" and "I said I'm done". It is a property of `handoff.sh`, not a separate service.

### 5.1 Fingerprint

```
fp = sha256( commit + "\n" + to + "\n" + task + "\n" + verdict + "\n" )
```

`commit` is the 10-char canonical form. Stored in `audit_pending/<task>.fp` as:

```
fp: <hex>
commit: <10hex>
challenged_at: <timestamp>
```

Written via `audit_pending/<task>.fp.tmp` + rename.

### 5.2 Algorithm

```
compute fp for this submission
if audit_pending/<task>.fp exists and its fp == this fp:
    → accept (caller proceeds to §4.6 step 2)
else:
    write audit_pending/<task>.fp with this fp   (overwrite)
    increment audit_count for <task> in board.tsv  (under board.lock)
    → challenge
```

Consequences:
- First submission of any candidate: always challenged.
- Identical resubmission: accepted.
- Changed candidate (new commit, different verdict, different recipient): challenged again, counter increments again. This is deliberate: the counter measures how many times the agent thought it was done.
- The `.fp` file survives agent restarts and machine reboots. A retried attempt (§6.4) that resubmits the same candidate is accepted without a second challenge.

### 5.3 Challenge output

```
AUDIT_REQUIRED: handoff for <task> not queued (audit <n>)
  Before resubmitting, re-read tasks/<task>.md and your role file.
  For every requirement in the task, find the commit, test, or output that proves it is met.
  If anything is missing, fix it, commit, and run handoff.sh again with the new commit.
  If everything is proven, run exactly the same command again to queue this handoff.
```

`<n>` is the new `audit_count`.

## 6. `role-loop.sh` — the per-role loop

One process per role, started by `conveyor start`, holding `loop.lock/` (§8.2) with its pid inside. A second loop for the same role MUST refuse to start (`loop already running, pid <p>`).

Environment set by the loop for every child: `CONVEYOR_ROLE`, `CONVEYOR_WORKTREE`, `CONVEYOR_ROOT` (repo root), `CONVEYOR_AGENT_BIN` (default `cursor-agent`; tests override).

### 6.1 Startup and recovery

```
n = count(inbox/in_process/*.handoff)
if n > 1:  print "ambiguous: <n> items in process"; exit 3   (human decides; §9)
if n == 1: process that item (§6.3) before reading new/
run delivery sweep (§6.5) for anything left in outbox/
```

Then the main loop.

### 6.2 Main loop

```
forever:
    if stop requested (§6.7): exit 0
    item = oldest file in inbox/new/ by filename sort
    if none: sleep 2; continue
    dequeue(item)
    process(item)
    delivery sweep
```

`dequeue`: rename `inbox/new/<f>` → `inbox/in_process/<f>`, then rewrite the file with `dequeued_at` and `attempt: 1` appended (write `<f>.tmp` in `in_process/`, rename over `<f>`). Update `board.tsv`: `lane` = this role, `updated_at`.

### 6.3 Processing an item

```
merge.sh <commit>                      (§7); on conflict → park(reason: merge-conflict)
check ceilings (§6.6); if exceeded → park
attempt = header attempt (1 on first pass; recovery re-reads it)
loop:
    prompt = build_prompt(item)        (§6.8)
    run agent (§6.9); capture session id
    outbox_count = count(outbox/*.handoff)
    if outbox_count == 1:
        stamp completed_at, outcome: forwarded|merged
        rename item → inbox/completed/
        break
    if outbox_count > 1:
        park(reason: multiple-handoffs)   -- ambiguous; never guess
        break
    -- zero: attempt failed
    attempt += 1; rewrite header
    if attempt > max_attempts:
        park(reason: max-attempts)
        break
    (loop; next prompt includes the last validator error, if any, and --resume <session>)
```

The loop never inspects the agent's text output to decide anything. Success is "exactly one valid file appeared in outbox", nothing else. A file in `outbox/` that fails to parse is moved to `failed/` and counts as zero.

### 6.4 Attempts vs. retries

- **attempt** (per item, `attempt` header): one agent invocation. Bounded by `max_attempts` (config, default 3). Exceeding it parks the item. Attempts after the first use `--resume <session>` when a session id was captured, so the agent continues rather than restarts.
- **retry** (per task, `retry_count` in `board.tsv`): one full coder → reviewer → `findings` cycle. Incremented by the reviewer's loop when it delivers a `findings` handoff. Bounded by `max_retries` (config, default 3). Checked by the coder's loop before processing (§6.6).

### 6.5 Delivery sweep

For each `outbox/<f>` (sorted):

```
parse; on failure → failed/<f> + failed/<f>.reason; continue
if sent/<f> exists: delete outbox/<f>; continue           -- already delivered
if to == done:
    merge into main (§7.3); on conflict → park + leave in outbox; continue
    board: lane=done, updated_at
    rename outbox/<f> → sent/<f>; continue
if id present anywhere under roles/<to>/inbox/:  rename outbox/<f> → sent/<f>; continue   -- crashed after delivery
write roles/<to>/inbox/tmp/<f> with enqueued_at appended
rename roles/<to>/inbox/tmp/<f> → roles/<to>/inbox/new/<f>
if verdict == findings: board retry_count += 1
board: lane=<to>, updated_at
rename outbox/<f> → sent/<f>
```

Every step is safe to repeat. The "id present anywhere" check is what makes a crash between the two renames harmless.

### 6.6 Ceilings

Checked at the start of §6.3, never mid-run:

| Ceiling | Source | Test | Park reason |
|---|---|---|---|
| `max_retries` | config per role (applies to `coder`) | `retry_count > max_retries` | `max-retries` |
| `max_minutes` | config per role | `now − first dequeued_at for this task_id > max_minutes` | `max-minutes` |
| `max_attempts` | config per role | §6.3 | `max-attempts` |

"First `dequeued_at` for this task_id" is found by scanning `roles/*/inbox/{in_process,completed}/` and `sent/` for the earliest `dequeued_at` with matching `task_id`. Cache it in the board row as `started_at` (§8.1) on first observation to avoid rescanning.

### 6.7 Stop

`conveyor stop` writes `.conveyor/roles/<role>/stop` (empty file). The loop checks for it at the top of each iteration and between attempts, finishes the current agent run if one is in flight, and exits 0, deleting the sentinel. `conveyor start` deletes any stale sentinel before launching.

A loop MUST NOT kill a running agent on stop. `conveyor stop --now` sends `TERM` to the agent, marks the item's `attempt` as failed, and leaves it in `in_process/` for recovery.

### 6.8 Prompt construction

The prompt passed to the agent, in this order, separated by blank lines:

1. `Re-read your role and constitution.`
2. `Task: <task>` followed by the full text of `tasks/<task>.md` at the merged commit.
3. `Inbound handoff:` followed by the item's headers and body verbatim. (For a `findings` handoff this is where the coder sees the reviewer's findings.)
4. If attempt > 1: `Your previous attempt ended without a valid handoff. Last validator output:` followed by the captured stdout of the last `handoff.sh` call, if the loop can find one in the run log; otherwise `No handoff.sh call was observed.`
5. `When finished, write ./tmp/handoff.txt and run handoff.sh ./tmp/handoff.txt. Do not end your run until it prints OK.`

Role instructions themselves are not in the prompt; they are in `.cursor/rules/conveyor-role.mdc`, which Cursor loads from the worktree root. The loop verifies that file exists before each run (`E_NO_RULES` in the log; park with reason `no-rules`).

### 6.9 Running the agent

```
cd $CONVEYOR_WORKTREE
$CONVEYOR_AGENT_BIN -p --force --model <model> --output-format stream-json [<cli-args>] [--resume <session>] "<prompt>" \
    > $CONVEYOR_ROOT/.conveyor/logs/<role>/<task>_<id>_a<attempt>.jsonl 2>&1
```

The loop records the exit code as the last line of the log (`{"type":"conveyor","exit":<n>}`) and extracts the session id from the first event that carries one. Exit code is informational only; §6.3's outbox check decides.

### 6.10 Parking

```
mkdir -p needs-human/<task>/
rename inbox/in_process/<f> → needs-human/<task>/item.handoff     (or outbox/<f> for a done-merge conflict)
write needs-human/<task>/reason:   <reason>\n<one line of detail>\n<timestamp>
board: lane=needs-human, updated_at
```

`conveyor resume <task> [--to <role>]` (default `--to` = the item's `to`, or `coder` for a coder item) renames `item.handoff` into `roles/<role>/inbox/new/` under its original filename, resets `attempt` to 1 in the header, and sets the board lane. `retry_count`, `audit_count`, and `task_id` are never reset. The operator is expected to have fixed something first (edited the task file and committed on main, or fixed the conflict); Conveyor does not check.

## 7. `merge.sh` and integration

### 7.1 Usage

`merge.sh <commit>` with cwd = worktree, env as §6. Exit 0 = merged or already present; exit 1 = conflict (tree left in conflicted state for the operator; the loop parks).

### 7.2 Algorithm

```
git fetch is not needed: all worktrees share one object store
if git merge-base --is-ancestor <commit> HEAD: exit 0            -- idempotent
git merge --no-edit <commit>
    → conflict: git merge --abort; exit 1
    → ok: exit 0 (merge commit gets byline via hook, §7.4)
```

`--no-ff` is not used; fast-forwards are fine and keep history linear when only one role has moved.

### 7.3 Merge into main on `done`

The reviewer's loop runs `merge.sh <commit>` with cwd = `$CONVEYOR_ROOT` (the main checkout) and `CONVEYOR_ROLE=operator`, so the merge commit is signed `By operator.`. Conflict → park with the outbox file left in place; `conveyor resume` after a manual merge re-runs the sweep, which finds the commit already an ancestor and completes normally.

Open question 3 in the PRD (auto-merge vs. leave branch) is resolved here as auto-merge; change §6.5's `done` branch to "rename to sent, board lane=done, no merge" if the other answer is chosen.

### 7.4 Byline hook

`commit-msg` hook installed by `conveyor start` in the shared `.git/hooks/`:

```
role = $CONVEYOR_ROLE, or "operator" if unset
if last non-empty line of message != "By <role>.": append "\n\nBy <role>.\n"
```

The hook is shared, so any human commit made without the env var is signed `By operator.`, which is correct.

## 8. Board

### 8.1 `board.tsv`

Tab-separated, no header row, one task per line, LF endings:

```
name  lane  created_at  updated_at  task_id  audit_count  retry_count  started_at
```

| Column | Rule |
|---|---|
| `name` | task name (§3.2) |
| `lane` | a role name, `needs-human`, or `done` |
| `created_at` | when `conveyor task` created it |
| `updated_at` | last lane or counter change |
| `task_id` | `<created_at_compact>-<name>`; stable for the row's lifetime |
| `audit_count` | integer; written only by `handoff.sh` |
| `retry_count` | integer; written only by the reviewer's loop |
| `started_at` | first `dequeued_at` observed for this task_id; `-` until known |

`conveyor task <name>` refuses a name already present (any lane). Deleting a row (`conveyor task --delete <name>`) and recreating it yields a new `task_id` with counters at 0.

### 8.2 Locks

All locks are directories, created with `mkdir` (atomic on POSIX, portable to macOS without `flock`):

```
acquire: for up to 30 s: mkdir <lock>/ && break; sleep 0.1
         write $$ to <lock>/pid
release: rm -r <lock>/
```

A lock whose `pid` is not a live process is stale; the acquirer may remove it and retry once. Locks: `board.lock/`, `roles/<role>/seq.lock/`, `roles/<role>/loop.lock/`.

### 8.3 Board writes

Every board write: acquire `board.lock/`, read whole file, modify the one row, write `board.tsv.tmp`, rename over `board.tsv`, release. Rows are never edited in place.

## 9. Invariants

These are the properties tests assert. Each is stated so that violating it is detectable from the filesystem alone.

1. **Single writer per directory.** No two actors ever create files in the same directory (table in §2.3).
2. **At most one in-process item per role**, except transiently during recovery, where the loop refuses to proceed rather than pick.
3. **Every state change is a rename.** No file is ever written in place in `outbox/`, `inbox/*`, `sent/`, `needs-human/`, `board.tsv`.
4. **Exactly-once delivery.** For any `id`, at most one file with that id exists across `roles/<to>/inbox/{new,in_process,completed}` and `needs-human/`, and a file with that id exists in `roles/<from>/sent/` once delivered.
5. **Idempotent merge.** Running `merge.sh <c>` twice leaves the tree identical to running it once.
6. **Bodies are immutable.** The body of a handoff in `sent/`, `inbox/*`, or `needs-human/` is byte-identical to the commit message of its `commit`.
7. **Identity is never agent-supplied.** `from`, `commit`, `id`, `task_id`, `type`, and all timestamps are absent from every draft and present in every installed handoff.
8. **Audit precedes queueing.** No handoff reaches `outbox/` without an accepted fingerprint; `audit_count ≥ 1` for every task with a handoff in any `sent/` other than `operator`'s.
9. **Counters are monotonic.** `audit_count` and `retry_count` never decrease for a given `task_id`.
10. **Bylines are total.** Every commit reachable from any `conveyor-<role>` branch, made after `conveyor start`, ends with `By <role>.` for the role whose worktree made it.
11. **Restart is a no-op on state.** Killing every loop at any instant and running `conveyor start` results in the same set of files in `completed/`, `sent/`, `done` lanes, and `needs-human/` as an uninterrupted run, modulo timestamps.
12. **Ambiguity parks; it never guesses.** More than one outbox file, more than one in-process item, a merge conflict, or a missing rules file all end in `needs-human/` or a refused start, never in a chosen branch.

## 10. Operator CLI (protocol-relevant subset)

| Command | Effect in protocol terms |
|---|---|
| `conveyor start` | Create worktrees, write rules files, install hook, create queue dirs, delete stale `stop` sentinels, launch one loop per role. |
| `conveyor stop [--now]` | §6.7. |
| `conveyor task <name> [< text]` | Validate name; write and commit `tasks/<name>.md` on main (`By operator.`); append board row (lane `coder`, counters 0); write an operator handoff `to: coder`, `verdict: ready`, `commit` = main HEAD, into `roles/operator/outbox/`; run the operator delivery sweep (§6.5) immediately. |
| `conveyor status` | Print §2.3 state for each role, `needs-human/` with reasons, and `board.tsv`. Pure read. |
| `conveyor log <role> [<task>]` | Pretty-print the newest matching `.jsonl`. Pure read. |
| `conveyor resume <task> [--to <role>]` | §6.10. |

The operator's `task` command is the only place a handoff is created without `handoff.sh`. It MUST produce a file that passes every check in §4.2–4.4 with `from: operator`, and it goes through the same audit-free path because the operator is the human; `audit_count` is not incremented.
