# Stage 3 — Workflow CRUD

> **Implemented 2026-09-04.** Suite went 120 → 206. What shipped matches this
> plan; the deviations are noted inline as **[as built]**.

## Context

Conveyor's pipeline shape is whatever `conveyor.conf` says. There is exactly one of it, and
the only way to change it is `conveyor pack two|three`, which picks between two hardcoded
role orders. The design package in `design_handoff_conveyor/` replaces that with named,
saved workflows the operator can create, edit, duplicate, delete and activate — the last
piece of the redesign that still has no implementation.

Stages 0–2 laid the groundwork: the spec was reconciled to the real filesystem, pipelines
of any length with a declared `gate <role>` now load and route correctly, and the UI was
split into Workflow and Roles tabs. Stage 3 is what those were for.

**Storage decision (locked in Stage 0):** `conveyor.conf` stays the single source of truth
for the *active* pipeline — it is what the role loops and `bin/handoff.sh` read, and what
`config.routes()` derives the permitted handoff triples from. Workflows are saved presets
layered on top:

```
conveyor.conf                      ACTIVE pipeline. Regenerated by "make active".
.conveyor/workflows/<slug>.json    { name, description, roles[], gate }
.conveyor/active                   "<slug>"
```

Nothing in the protocol surface moves, and no invariant test changes.

## The blocker to fix first

**A three-role workflow with no gate is currently inexpressible**, and the design's own seed
list ([design_handoff_conveyor/README.md:150](design_handoff_conveyor/README.md#L150)) contains
one: *"Spec, no gate"*.

[config.py:74-83](lib/conveyor/config.py#L74-L83) infers a gate for any three-role config with
no `gate` line — Stage 2's backward-compatibility rule, which reproduces the original
three-pack hold for configs written before `gate` existed. So a preset saying `gate: null`
would activate into a silently *gated* pipeline. Worse, `config.save()` writes
`cfg.gate_role()`, so it would even write `gate specifier` into the file.

### Fix: a `gate none` sentinel

| `conveyor.conf` | `gate_role()` |
| --- | --- |
| `gate specifier` | `"specifier"` |
| `gate none` | `None` — explicitly ungated |
| no gate line, 3 roles | `names()[0]` — legacy inference, unchanged |
| no gate line, any other count | `None` |

- `Config.gate` keeps the declared string: `""` undeclared, `"none"` explicit, else a role.
- `config.save()` **always** writes a gate line, `gate <role>` or `gate none`. Every file
  Conveyor writes is self-describing; only hand-written legacy files rely on inference.
- Add `"none"` to `config.RESERVED` so no role can be named it. Nothing is named `none` today.
- `gate none` is valid at any role count, including one role.

This is backward compatible and about 15 lines. **Do it first, in isolation, with the suite
green before anything else** — it is the only change that can silently corrupt an operator's
`conveyor.conf`.

Existing test to update: `test_pipeline_shape.py::test_save_omits_the_gate_when_there_is_none`
becomes `test_save_writes_gate_none_when_there_is_no_gate`.

## Locked decisions

| Decision | Choice |
| --- | --- |
| No-gate expressibility | `gate none` sentinel (above) |
| HTTP shape | **POST-only with action suffixes**, matching the codebase — not the spec's PUT/DELETE. `httpd.py` implements only `do_GET`/`do_POST`; new verbs would each duplicate the ~10-line exception mapping, widen the CORS allow-list, and need new test helpers. Deletion is already `POST /api/tasks/delete`. Record the deviation in `bin/README.md`. |
| Stale worktrees | **Prune in `conveyor start`, never `--force`** |
| Slug | Allocated at create, **immutable**. Not stored in the file — the filename is the only source, so it cannot drift. Renaming changes the display name only, and `.conveyor/active` can never dangle. |

## 1. `lib/conveyor/presets.py` (new)

A new module, not an extension of [workflows.py](lib/conveyor/workflows.py) — that file's
docstring says identity is *inferred, never stored*, and Stage 3 inverts exactly that.
`workflows.py` keeps avatars, chrome and `library_roles`. No import cycle: `presets` imports
`config`/`util`/`layout`.

**This is the repo's first persisted JSON.** State the convention in the module docstring so
Stage 4's `jira.json` follows it: `json.dumps(data, indent=2)` with an explicit key order
(`name, description, roles, gate`, not `sort_keys`) plus a trailing newline, written through
[`util.atomic_write`](lib/conveyor/util.py). Read with `json.loads(util.read_text(path))`.

```python
class PresetError(ValueError):
    """Bad preset shape. Subclasses ValueError so httpd maps it to 400."""

def slug(name)                     -> str
def validate(root, data)           -> dict          # normalized; raises PresetError
def load(paths, s)                 -> dict          # +"slug"; raises FileNotFoundError
def load_all(paths)                -> list[dict]    # by name.lower(); skips unparseable
def allocate_slug(paths, name)     -> str           # base, base-2, base-3 …
def save(root, paths, s, data)     -> dict
def create(root, paths, data)      -> dict
def delete(paths, s)               -> None
def ensure_seeded(paths)           -> None
def read_active(paths)             -> str           # "" when absent
def resolve(paths, cfg)            -> (slug|None, "active"|"modified"|"custom")
def routes(preset)                 -> list          # belt edges, no intake edge
def activate(root, paths, cfg, s)  -> dict
```

Reuse [`inbox.py`](lib/conveyor/inbox.py)'s `slug`/`allocate_id` shape for slug allocation and
its `FileNotFoundError` → module-error mapping.

### `layout.Paths` additions

Following the existing convention in [layout.py:35-47](lib/conveyor/layout.py#L35-L47):

```python
self.workflows      = os.path.join(self.conveyor, "workflows")
self.workflows_lock = os.path.join(self.conveyor, "workflows.lock")
self.active         = os.path.join(self.conveyor, "active")
```

Do **not** add `workflows` to `ensure()` — `presets.ensure_seeded()` owns creation so that
"directory absent" is a usable one-shot seed signal.

### Validation errors

All raise `PresetError` → HTTP 400 / `util.die`. Keep the gate messages **verbatim-parallel to
`config.py`'s**, so the operator reads the same sentence whichever layer refuses:

| Condition | Message |
| --- | --- |
| blank name / `slug(name) == ""` | `name must contain at least one letter or digit` |
| empty `roles` | `roles must list at least one role` |
| fails `config.ROLE_RE` or in `config.RESERVED` | `invalid role name 'X'` |
| duplicate | `role 'X' appears twice; a role may be on the belt at most once` |
| no `roles/<X>.md` | `unknown role 'X'; create roles/X.md first` |
| gate off the belt | `gate names a role that is not on this belt: 'X'; repair: gate one of a, b, c` |
| gate on the last role | `cannot gate 'X', the last role — its handoff goes to done, not to another role; repair: gate a role before it, or set gate to null` |

Never let `config.ConfigError` escape a preset call — `httpd` maps it to 500. Wrap it.

### Seeding

`ensure_seeded` returns early if `paths.workflows` exists, so a deleted seed stays deleted.
Four seeds, matching the design's list: `review-belt`, `spec-then-build`, `spec-no-gate`
(three roles, `gate: null` — now expressible), `solo-coder` (one role).

Called from every `conveyor workflow` subverb, from `cmd_start`, and from
`state.build_workflows`.

**Companion change:** `ensure_seeded` creates `.conveyor/`, and
[state.py:90](ui/server/state.py#L90) does `initialized = os.path.isdir(paths.conveyor)` — a
UI GET on a never-started repo would flip `initialized` to True. Change it to
`os.path.isfile(paths.board)` ("conveyor has run here"). Add a test.

### Locking

Individual preset writes need no lock — `atomic_write` means a reader never sees a partial
file, and last-write-wins is harmless for one operator. `activate` and `delete` take
`util.lock(paths.workflows_lock)`, because `activate` writes two files that must agree and
races `state.update_role_runtime`, which also calls `config.save`.

## 2. `presets.activate`

Mirrors [`cmd_pack`](bin/conveyor)'s carry-over rule exactly:

- A role the preset **keeps** reuses the *same `config.Role` object*, so `model`, all three
  ceilings and `role.args` survive verbatim.
- A role the preset **adds** gets `fallback.model` (the current first role's model) and
  ceilings from a `ROLE_DEFAULTS` map for the three shipped roles (`specifier` 3/60/2,
  `coder` 3/120/3, `reviewer` 3/60/2), else `config.Role`'s dataclass defaults. This is five
  lines and makes activating `spec-then-build` byte-identical to today's `conveyor pack three`.
- `cfg.gate = preset["gate"] or "none"` — with the sentinel fix, `save()` writes exactly that.

**Write order: `conveyor.conf` first, `.conveyor/active` second.** A crash between them leaves
the *pipeline* correct — that is what the loops and `handoff.sh` read — and only the cosmetic
marker stale. The reverse would leave the marker claiming a pipeline that is not configured.

Refuses while loops run, reusing `cmd_pack`'s message with one word changed.

### Staleness — `resolve(paths, cfg)`

Never trusts the marker blindly:

1. If any preset satisfies `roles == cfg.names() and gate == cfg.gate_role()` →
   `(slug, "active")`, preferring the slug in `.conveyor/active` when several match. This
   self-heals the crash window above.
2. Else if `.conveyor/active` names an existing preset → `(slug, "modified")`.
3. Else `(None, "custom")`.

A hand-edit of `conveyor.conf` shows the row as `modified`; the UI renders the real chain from
`conveyor.conf` and never tries to reconcile. The match is on `(roles, gate)` only — a model or
ceiling change is **not** "modified", because presets do not carry models. Say so in the
detail-page copy.

## 3. CLI — `bin/conveyor`

```
conveyor workflow list
conveyor workflow show <slug>
conveyor workflow new <name> --roles a,b,c [--gate <role>] [--description <text>]
conveyor workflow edit <slug> [--name <text>] [--description <text>]
                              [--roles a,b,c] [--gate <role> | --no-gate]

conveyor workflow activate <slug>
```

- `--roles` is comma-separated, no spaces, so the existing `_flag`/`_positionals` helpers work
  unchanged.
- `--no-gate` lets `edit` distinguish "leave the gate alone" from "clear it".
- `edit` with no mutating flag → `util.die("conveyor workflow edit: nothing to change")`.
- `edit` never moves the file when `--name` changes (slug is immutable).
- `new` auto-suffixes a taken slug, which makes the UI's **Duplicate** a plain `new`.
- `delete` refuses the active preset and refuses the last remaining one (`RuntimeError` → 409).
- `activate` prints the new chain, the marker, the restart hint, and `cmd_pack`'s existing
  leftover-worktree warning amended to point at the new pruning.

**`conveyor pack` is deleted**, as Stage 1 promised, along with `packs/three-pack.conf.example`
(nothing in `SHIPPED` references it; the `spec-then-build` seed replaces it).

## 5. `prune_stale_worktrees` in `cmd_start`

[bin/README.md](bin/README.md) invariant 21 claims `git worktree remove` "would take the role's
`conveyor-<role>` branch with it". **That is false** — `worktree remove` deletes the working
directory and admin files only; branch deletion is `git branch -d/-D`. Correct the invariant in
the same commit, and state the real reason pruning is safe.

Rules, each load-bearing:

1. **Enumerate from `git worktree list --porcelain`**, not `os.listdir`. Keep a candidate only
   if git reports it, its path is exactly `paths.worktree(name)` (via `realpath`, for
   case-insensitive filesystems), and its branch is exactly `refs/heads/conveyor-<name>`. Parse
   `\n\n`-separated stanzas, do not line-scan.
2. **Skip `ticket-reviewer`.** `cmd_intake` creates `.worktrees/ticket-reviewer` and it is never
   in `cfg.names()`. Missing this breaks `conveyor intake` on every start — the obvious trap.
3. **Skip any role with a live loop** (`layout.loop_pid`) and warn.
4. **Never `--force`.** `util.git_ok(["worktree","remove",wt], root)`. Success →
   `removed stale worktree .worktrees/<name> (branch conveyor-<name> kept)`. Failure → today's
   warning naming the manual `--force` command, so uncommitted work is never destroyed.
5. **Never `git branch -d/-D`** and **never touch `.conveyor/roles/<name>/`** — it holds
   `sent/`, `completed/` and `audit_pending/`, the actual audit trail.

Call site: in `cmd_start`, after `paths.ensure(cfg)` / `install_hook(root)`, before the
`ensure_worktree` loop. **Not** in `activate` — that stays a pure config write.

## Risks

| # | Risk |
| --- | --- |
| 1 | **`config.save` writing an inferred gate.** Silent and config-corrupting. Closed by step 1 and a named test; nothing else may land first. |
| 2 | **`ticket-reviewer`'s worktree is not in `cfg.names()`** and a naive prune deletes it, breaking `conveyor intake`. Explicit skip, explicit test. |
| 3 | **Two similarly named endpoints** — `/api/workflow` (active belt, used by Roles) and `/api/workflows` (preset CRUD). Justified but a readability hazard; document both in a route table at the top of `httpd.py`. |
| 4 | **`.conveyor/` is gitignored**, so presets are per-checkout and never shared with a team. Matches the spec; will surprise someone. One sentence in `bin/README.md`. |
| 5 | **A preset can reference a role file later deleted.** `validate` runs on both save and activate, so activation fails cleanly; the list page must render such a row with a warning rather than 500. |
| 6 | **Race between the running-loops check and `config.save`** in `activate` — the lock does not cover `conveyor start`. Negligible for one operator; note it in a comment rather than pretending it is closed. |
| 7 | **Pruning a worktree is only branch-safe until the role returns** — `ensure_worktree`'s `-B` would then reset `conveyor-<role>` to HEAD. Acceptable, but say so in the corrected invariant 21 rather than claiming pruning is free. |
